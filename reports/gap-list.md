# Gap List

## Purpose

Record known gaps after SEIS assembly.

## Gaps

| Gap | Severity | Required Evidence Or Fix |
| --- | --- | --- |
| No paid first-wedge signal | High | Discovery calls, paid pilot, signed audit, or equivalent commitment |
| No external audit | High | Independent review packet and findings |
| Historical docs still large and mixed | Medium | Deprecation index and cleanup branch |
| First wedge distribution untested | High | Channel tests and response metrics |
| Protocol/credit/capital are placeholders | Expected | Repeated delivery standards before implementation |
| Case library is empty for SEIS wedge | High | First accepted delivery and proof package |
| Pricing ladder unvalidated | Medium | Real quote, objection, close/loss reason |
| App/workbench not implemented | Expected | Repeated validated workflow patterns and explicit implementation approval |
| Product/SaaS not launched | Expected | Paid delivery evidence, retention/use evidence, support model, and launch approval |
| Stage 16 not completed | Expected | Multi-stage evidence across standards, protocol, rights, clearing, credit, and capital allocation |
| Untracked production-spine files not audited | Low | Separate review if user wants them incorporated |
| Full `make ci` not run after assembly | Medium | Run after staging/committing or on a clean verification branch |

## Non-goals

- Gaps are not failures of this assembly if they require real-world action.
- Do not close market gaps with more internal docs.
- Do not close app, SaaS, protocol, credit, clearing, certification, or
  Stage 16 gaps with scaffold language.

## Upgrade Path

Close gaps through buyer contact, paid delivery, external review, and
evidence-backed registry updates.
