# Proof Asset Spec

## Purpose

Define the minimum proof package for any SEIS delivery.

## Scope

Applies to case studies, demos, before/after records, ROI notes, service
pages, and credibility packs.

## Non-goals

- Do not expose secrets or private client data.
- Do not imply certification.
- Do not claim results that are not evidenced.

## Required Fields

| Field | Requirement |
| --- | --- |
| Claim | Specific outcome, not vague value |
| Buyer context | Role, industry, trigger, anonymized if needed |
| Baseline | Before state and evidence available |
| Intervention | What SEIS delivered |
| Acceptance | Who accepted and by what criteria |
| Evidence | Artifacts, tests, screenshots, hashes, reports, or signed notes |
| Limitation | What was not proven |
| Reuse asset | Template, SOP, objection, benchmark, failure, or registry update |
| Distribution asset | Post, service page, demo, referral ask, or technical breakdown |

## Operating Rules

- No proof asset ships without limitation statement.
- Sensitive data must be redacted or summarized.
- Internal demos are labeled internal.

## Failure Modes

- Proof becomes marketing copy without evidence.
- A single case is inflated into market dominance.
- Private evidence leaks.

## Upgrade Path

Add proof package schemas after repeated deliveries reveal stable fields.
