# Tool Reliability Records

    ## Purpose

    Record tool reliability and failure rates.

    ## Scope

    Asset compounding registries.

    ## Non-goals

    - This file is not evidence of revenue, customer adoption, external certification, or Stage 16 completion.
    - It does not authorize uncontrolled automation, secret handling, account changes, or live provider execution.
    - It does not replace human approval for high-risk decisions.

    ## Operating Rules

    - Every delivery must update at least one registry.
- Registry entries must separate assumption, internal evidence, and external proof.
- Existing `assets/houdini/` remains a production artifact tree, not market proof.

    ## Failure Modes

    - The file is used as vague strategy prose without a named buyer, budget source, buying trigger, trust gap, and proof artifact.
    - Operators claim market proof where only repository scaffold, policy, template, or internal evidence exists.
    - A low-tier worker model is allowed to make final strategic, architecture, risk, or market-selection decisions.
    - The system expands runtime capability before the transaction, proof, and trusted-delivery requirements are bounded.

    ## Upgrade Path

    - Attach real delivery records, buyer objections, pricing outcomes, acceptance results, and failure records.
    - Convert repeated decisions into scorecards, policy gates, schemas, tests, and evidence packages.
    - Promote only after proof exists for the maturity stage being claimed.
