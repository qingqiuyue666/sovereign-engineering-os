# Delivery To Asset Conversion Rules

## Purpose

Define how a real delivery becomes reusable SEIS leverage.

## Conversion Rules

| Delivery Signal | Convert To | Required Evidence |
| --- | --- | --- |
| Accepted audit with permission | Case-library entry. | Handoff, acceptance, redaction approval, limitation statement. |
| Incomplete or failed delivery | Failure-library entry. | Failure record, cause, impact, prevention rule. |
| Repeated buyer pain | Customer-problem-library entry. | Discovery notes or delivery records across targets. |
| Repeated objection | Objection-library and service-page update. | Objection log, response outcome, revised language. |
| Price response | Pricing-history entry. | Buyer role, scope, price, outcome, budget source. |
| Measured workflow metric | Benchmark-history entry. | Baseline, method, date, limitation. |
| Measured economic result | ROI-history entry. | Before/after measurement and caveat. |
| Tool or model issue | Tool-reliability record. | Tool, task, failure mode, mitigation. |
| Template reused | Template-reuse-ledger entry. | Project, template, result, modification. |
| SOP repeated | Standardization candidate. | Reuse count, acceptance records, risk review. |

## Objection-to-Offer Rule

Repeated objections should update pricing, service-page language, discovery
questions, rejection rules, or scope. Do not update claims beyond evidence.

## Failure-to-Rule Rule

Every material failure must produce one of:

- a new rejection rule
- a review gate
- a template change
- a risk-tier rule
- a scope exclusion
- a buyer evidence requirement

## Standardization Rule

No template becomes an SOP without repeated use. No SOP becomes a standard
without repeated accepted delivery and auditor review. No standard supports
certification, protocol, credit, clearing, or capital language without
additional external evidence.
