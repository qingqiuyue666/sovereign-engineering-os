# Control Point Scorecard

## Purpose

Score whether a wedge can become a defensible economic control point.

## Scope

Applies before market selection, offer design, and protocol pre-structure.

## Non-goals

- A score is not proof.
- A score does not override buyer evidence.
- This scorecard does not claim control-point capture.

## Scorecard

| Criterion | 1 | 3 | 5 |
| --- | --- | --- | --- |
| Budget control | Buyer unclear | Budget owner inferred | Budget owner named |
| Trigger control | No urgency | Periodic pressure | Time-bound forced action |
| Trust verification | Nice-to-have | Some review need | Trust is purchase reason |
| Delivery standard | Ad hoc | Repeatable checklist | Standard candidate |
| Data compounding | Little reuse | Some templates | Cases, failures, benchmarks compound |
| Workflow embedding | One-off | Repeatable handoff | Embedded in production workflow |
| Distribution | No channel | Testable channel | Repeatable buyer access |
| Rights/credit/clearing path | None | Possible later | Natural responsibility/ownership need |
| Anti-platform resilience | Platform can absorb | Partial differentiation | Independent trust/control point |
| Anti-commodity resilience | Output commodity | Some specialization | Risk/trust/standard premium |

## Operating Rules

- Total below 35/50 requires rejection or explicit human override.
- Any score of 1 in budget, trigger, or trust requires a gap plan.
- Update scores after discovery and delivery.

## Failure Modes

- Scoring reflects optimism instead of evidence.
- Data compounding is claimed without a registry.
- Anti-commodity resilience is confused with feature quality.

## Upgrade Path

Bind scores to real case records after the first paid delivery.
