# Standardization Candidate Ledger

## Purpose

Track which repeated delivery patterns may become standards after sufficient
evidence.

## Candidate Ledger

| Candidate | Source Deliveries | Reuse Count | Accepted Outcomes | Failures | Evidence Links | Readiness | Next Review |
| --- | --- | ---: | --- | --- | --- | --- | --- |
|  |  | 0 |  |  |  | not ready / SOP candidate / standard candidate / rejected |  |

## Readiness Gates

- SOP candidate: repeated template or workflow use with known limitations.
- Standard candidate: repeated accepted outcomes across comparable projects.
- Certification support: requires independent/external review readiness.
- Protocol support: requires stable evidence format and repeatable workflow.
- Credit/right/clearing support: requires economic contribution tracking and
  governance beyond service delivery.

## Boundary

This ledger does not create certification, protocol, credit, clearing,
rights, or capital-allocation status. It records candidates for future gates.
