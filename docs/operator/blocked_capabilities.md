# Blocked Capabilities

## Blocked Means Blocked

Blocked means blocked. A blocked capability is not hidden-ready, not dormant-ready, and not enabled by operator preference. It remains unavailable until a separate authorized slice adds tests, audit coverage, and human review.

## Real Provider Execution

Real provider execution remains blocked. This repository may define contracts, preflights, and receipts, but this private production layer does not execute live providers.

## Production Autonomy

Production autonomy remains blocked. No component in this private operator layer may turn reports, plans, or handoff packets into autonomous production action.

## External Actions

External actions remain blocked. The private operator layer must not execute real external actions, launch external tools, or mutate systems outside the repository.

## Financial Execution

Financial execution is out of scope. This repository does not place orders, allocate capital, route orders, execute leverage, or connect to broker execution.

## Network Execution

Network execution is blocked for new runtime modules in this slice. Contracts must accept caller-provided material and render deterministic output.

## Subprocess Execution

Subprocess execution is blocked for new runtime modules in this slice. Validators and renderers must not launch tools or shell commands.

## Environment / Secret Access

Environment value access is blocked. Secret, credential, token, API key, password, private key, and authorization material must not be read, persisted, or transmitted.

## Trading Automation

Trading automation is blocked. Auto-buy, auto-sell, order routing, full-position execution, leverage execution, broker/API execution, and autonomous trading are forbidden.

## Conditions Required Before Any Future Unblock

Any future unblock requires a separate authorized slice, explicit tests, audit coverage, human review, and merge approval. The unblock must preserve existing governance, security, classification, audit, evidence, provider transport, local runtime, durable store, health, and CI contracts.
