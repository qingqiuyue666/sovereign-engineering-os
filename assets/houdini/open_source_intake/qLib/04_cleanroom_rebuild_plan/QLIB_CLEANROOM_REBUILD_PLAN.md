
# qLib Clean-Room Rebuild Plan v1

## Goal

Use qLib as a technical reference while preserving HFX Factory control over naming, interface, manifests, validation, and shot binding.

## Process

1. Select candidate qLib asset or pattern.

2. Record upstream path and license.

3. Describe behavior in neutral terms.

4. Identify HFX Core12 target asset.

5. Rebuild the behavior inside HFX conventions.

6. Use HFX parameter naming.

7. Use HFX cache/pass/output contracts.

8. Generate preview.

9. Run HFX validation.

10. Only then promote to production candidate.

## Prohibited

- Blind copy into HFX Core12 production folders.

- Hidden dependency import.

- License removal.

- Local machine path retention.

- Secret or credential inclusion.

- Claiming film-grade status without shot validation.
