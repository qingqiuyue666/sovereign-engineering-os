# Candidate Wedges

## Purpose

Define the current wedge set and prevent drift into generic AI services.

## Scope

Four wedges: AI Engineering Production Governance, Trusted AI Workflow
Transformation, Trusted Content / E-commerce Supply Chain, and High-Trust
Local / Private AI Systems.

## Non-goals

- These are not proven markets yet.
- This file does not claim revenue or adoption.
- This file does not authorize runtime expansion.

## Wedges

| Wedge | Not This | Real Wedge | Primary Trust Gap |
| --- | --- | --- | --- |
| A | Shallow code review | AI-written code entering production through audit, tests, rollback, review gates, evidence chains, risk classification, and task packages | Production acceptance of AI code |
| B | Generic automation | Auditable, maintainable, reusable AI work systems for real small-team processes | Process reliability and ownership |
| C | Generic content generation | Full content supply chain from product data to review, publish precheck, reuse, tests, and performance feedback | Content accuracy and commercial proof |
| D | Generic local RAG | Private/local AI systems for sensitive data, local search, permissions, audit, and trusted delivery | Data sensitivity and permission boundary |

## Operating Rules

- Wedge A is provisional first wedge.
- Wedge B and D are fallback/second wedges.
- Wedge C requires stronger distribution or niche proof before first use.

## Failure Modes

- Selling generic AI automation.
- Ignoring buyer budget and trigger.
- Entering platform-owned commodity markets.

Convert real discovery notes into wedge score revisions.
