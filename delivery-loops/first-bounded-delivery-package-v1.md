# First Bounded Delivery Package V1

Status label: `FIRST_BOUNDED_DELIVERY_PACKAGE_READY`

Repository status: `SEIS_REAL_WORLD_VALIDATION_READY`

Real-world status: `HUMAN_ACTION_REQUIRED`

## Purpose

Prepare one small, safe delivery package that can be offered only after a real
buyer or operator accepts scope.

This is not a completed delivery, case study, ROI record, or product.

## Package Name

`One Workflow Safety Upgrade`

## One-Workflow Rule

Each delivery covers exactly one workflow.

Supported examples:

- order/report spreadsheet cleanup
- daily or weekly report generation
- file naming and archive workflow
- customer information cleanup
- content publishing checklist and preparation
- recruiting/application screening workflow
- simple admin or operations repetitive task

Do not combine multiple workflows into one first delivery.

## Intake

Capture:

- target identifier
- workflow owner
- workflow name
- current trigger
- current inputs
- current outputs
- current tools
- current pain
- frequency
- time cost
- error cost
- approval owner
- data sensitivity
- risk boundary
- evidence access

## Current-State Map

Map:

1. trigger
2. source artifacts
3. manual steps
4. judgment steps
5. approval steps
6. output
7. failure points
8. handoff
9. evidence available

## Risk Tier

| Tier | Meaning | Delivery rule |
| --- | --- | --- |
| low | Internal prep, no sensitive data, no external action. | Proceed if owner accepts scope. |
| medium | Customer, financial, HR, or account-adjacent data after redaction. | Require explicit review points and redaction rules. |
| high | Payments, account changes, production systems, regulated decisions, or external promises. | Reject, defer, or require separate approval outside this package. |

## Tool Boundary

Allowed:

- local files supplied by the user
- redacted samples
- checklists
- spreadsheets
- SOP drafts
- workflow maps
- human-reviewed output drafts

Forbidden:

- automatic payment
- automatic account changes
- automatic external promises
- bypassing platform rules
- secret handling
- high-risk browser automation without approval
- production system changes without approval
- sending final external messages without human confirmation

## Human Confirmation Points

Human approval is required before:

- using sensitive data
- changing a workflow rule
- sending anything externally
- changing account state
- treating output as final
- recording a stronger evidence claim
- publishing any case material

## Implementation Options

Choose only after discovery:

- checklist/SOP only
- spreadsheet cleanup template
- report-prep template
- file naming and archive convention
- draft-generation prompt and review checklist
- redacted data cleanup workflow
- manual handoff with evidence log

No provider integration or app implementation is included.

## Evidence Package

Every delivery should produce:

- intake summary
- current-state map
- accepted scope
- exclusions
- before/after artifact description
- SOP or checklist
- review points
- failure log
- handoff record
- limitation statement
- asset conversion decision

## SOP

The SOP must include:

- trigger
- owner
- inputs
- steps
- review points
- output
- acceptance criteria
- failure handling
- rollback
- maintenance note

## Handoff

Handoff must include:

- what changed
- what did not change
- how to run the workflow
- how to inspect output
- what to do when it fails
- what requires human approval
- what evidence supports the result

## Failure Handling

If delivery fails or is incomplete:

- stop the workflow change
- record failure type
- preserve evidence
- revert to prior workflow where possible
- update risk rules
- do not publish case material

## Rollback

Rollback means returning to the prior manual process, prior file structure,
prior checklist, or prior owner approval process.

Rollback must be possible before delivery begins.

## Maintenance Option

Maintenance may include:

- monthly SOP review
- small checklist updates
- failure log review
- workflow drift review
- evidence cleanup

Maintenance cannot be sold as proof of adoption until accepted by a real
buyer.

## Case Capture Template

After real delivery only, capture:

- target segment
- workflow
- baseline pain
- accepted scope
- output
- evidence
- limitation
- accepted / incomplete / rejected / failed outcome
- reusable asset decision

Do not create a case study from a template or hypothetical example.
